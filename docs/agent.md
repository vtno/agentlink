# Agent

`AgentLink.Relay.Agent` opens one agent through `AgentLink.Agent`. `AgentLink.Agent.Process` is the production behaviour. It runs the `command` and `args` from `AgentLink.Agent.Launch`. The default suite sets `:agent_link, :agent_module` to a fake. `test/lifecycle_test.exs` and `test/release_lifecycle_test.exs` set `AgentLink.Agent.Process` and start `test/fixtures/agentlink_hold_fixture.py`. `test/agent_process_test.exs` starts `test/fixtures/agentlink_setsid_fixture.py`. `test/launch_test.exs` uses a python3 stand-in for the Burrito launcher. Stdout still arrives as `{ref, {:data, binary}}`.

`AgentLink.Agent` is that behaviour. `open/3` takes the owner, an `AgentLink.Agent.Launch`, and the workspace. `write/2` and `close/1` stay as they are. A link's `program` is metadata. `opencode` is one example. `program` does not choose the module, the command, or the args. When `program` is missing, `AgentLink.Link` uses `opencode`.

Each `init/1` creates the workspace, then calls `AgentLink.Agent.Launch.load/1` once. That call returns the `AgentLink.Link` and the `AgentLink.Agent.Launch` from the same read. The relay passes that link to `AgentLink.Uplink` as `:link`. The uplink's `init/1` does not read the file again. A watch, a non-parking close, and an uplink started without `:link` call `AgentLink.Link.read/1`. `command` and `args` are not fields of `AgentLink.Link`. Changing only those fields does not redial and does not replace the running process. The next `init/1`, including a supervisor restart, calls `load/1` again. The launch is not stored in the supervisor child arguments.

`AgentLink.Agent.Process.open/3` is the behaviour callback. The relay calls `open/5` for this module and passes `:agent_open_listener`. `open/3` does not read application config. The caller must be `owner`. A bare name is resolved by the finder. `open/4` accepts that finder and is not a callback. The finder `open/3` uses is `&System.find_executable/1`. A path that is absolute on this host is used unchanged. On Unix that path starts with `/`. On Windows it starts with two slashes, or with a drive letter, a colon, and a slash. Each of those two slashes may be `/` or `\`. The slash after the colon may be `/` or `\`. On Windows, a single leading slash is not absolute. Any other command is rejected before `File.stat/1`. `File.stat/1` must report a regular file. `File.stat/1` follows symlinks. `open/3` then calls `Port.open/2` with `{:spawn_executable, path}`, `:binary`, `:exit_status`, `:use_stdio`, `{:args, args}`, and `{:cd, cwd}`. `:env` is the VM environment without `AGENTLINK_WINDOWS_START`. `:stderr_to_stdout` is omitted, so stderr is not merged into `{port, {:data, binary}}`.

On Linux the VM's port spawn makes the command a session leader, and that pid is the process group leader. `close/1` reads `/proc` and records the start time of that pid and of each descendant, including a descendant that called `setsid`. It signals `SIGTERM` only when that start time still matches. A group leader is signaled with the negative pid. A descendant whose process group is not that pid is signaled by its own pid. `close/1` then closes the port, which closes the child's stdin, and waits up to `:agent_stop_timeout` milliseconds. The default is `5000`. When a recorded start time still matches, `close/1` reads `/proc` again, signals `SIGKILL` the same way, and waits again. The second wait is `:agent_stop_timeout`, or `1000` milliseconds when that value is shorter, so a timeout of `0` still observes the reap. `close/1` returns `:ok` only when every recorded process is gone. It returns `{:error, :no_kill}` when `kill` is not on `PATH`. It returns `{:error, :kill_failed}` when `kill` exits non-zero and the start time still matches. It returns `{:error, :timeout}` when a start time still matches after `SIGKILL`. Those remaining `{pid, starttime}` pairs are kept by `AgentLink.Agent.Reaper`. When that process is not running, `retain/1` writes the pairs into this VM's file and returns `{:error, :noproc}`, and `close/1` returns that error.

`AgentLink.Agent.Reaper` starts before `AgentLink.Relay.Agent` in the same supervisor. The pairs are written to `agent-reaper-<pid>-<starttime>.bin`, using this VM's OS pid and start time. That file is under `:reaper_dir` when it is set, otherwise under `RELEASE_TMP`, otherwise under `~/.agentlink/run`. The file mode is `0600`. `init/1` reads this VM's file and drops a pid whose start time no longer matches, so a Reaper restart still blocks the next open and does not signal a recycled pid. Another VM's file is removed only when its pid does not exist, or when that pid exists and its readable start time differs from the real start time in the name. A stored start time of `0`, or a start time that cannot be read, is left in place, including on a machine without `/proc`. `init/1` removes this VM's `.bad-*` and `.tmp` files. Another live VM's file is not read and is not signaled. The term is `{:agentlink_reaper, 1, pairs}`. A short, undecodable, or other-version file is logged, renamed beside the record, and is not used to signal a process. Every load, modify, and save of this VM's file, and a clean shutdown's delete, runs inside `:global.trans/3` on `{{:agentlink_reaper, vm}, self()}`, limited to `[node()]`. The requester is the calling process. A `retain/1` during `init/1` waits for that lock and still leaves its pairs for the next `reap/0`. `init/1` verifies the pairs it loaded before it saves them. `retain/1` writes the pairs into this VM's file even when the Reaper is not running, then returns `{:error, :noproc}`. The next relay calls `reap/0` before `open/5` for `AgentLink.Agent.Process`. `reap/0` reads the file again, signals `SIGKILL` to each retained pid whose start time still matches, and waits `1000` milliseconds. The relay opens the new agent only when every retained start time is gone. When one remains, that start returns `{:stop, {:reap, reason}}` and does not call `open/5`. `reap/0` returns `{:error, :noproc}` when the Reaper is not running, and that start does not call `open/5`. A clean shutdown removes this VM's file.

On macOS, `close/1` closes stdin and does not signal a process group, does not walk descendants, and does not create a Job Object. On Windows, `close/1` closes stdin and does not signal a process group and does not create a Job Object. `write/2` returns `:ok` when the port is open and `:closed` otherwise.

`AgentLink.Release.forward_signals/1` wraps each Burrito binary `mix.exs` ships and compiles the wrapper with `zig cc`. The Linux target is `x86_64-linux-gnu` and the macOS target is `aarch64-macos`. Those wrappers install the `SIGTERM` and `SIGINT` handler before `fork`, put the Burrito process in its own process group, and forward one `SIGTERM` or one `SIGINT` to the VM. The VM is the Burrito process's direct child. The wrapper records that pid and start time. After the Burrito process exits, the wrapper keeps signaling that same pid when the start time still matches, including after the VM's parent becomes pid 1. It then waits `2000` milliseconds and signals `SIGKILL`. If the VM is still alive `2000` milliseconds later, the wrapper exits with status 1. When the VM exits from the forwarded signal, the wrapper exits with the Burrito process's status. A grandchild such as `erl_child_setup` is not the target. A forwarded `SIGINT` is delivered to the VM as `SIGINT`. The BEAM opens the Erlang BREAK prompt and the node stays up. The plain release does the same. `SIGTERM` is the stop signal. The Windows target is `x86_64-windows-gnu`. That wrapper runs the Burrito process in a Job Object with `KILL_ON_JOB_CLOSE`, turns Ctrl-C, Ctrl-Break, and console close into one Ctrl-Break for the child process group, waits `2000` milliseconds, and calls `TerminateJobObject` if the child is still running. A forced stop exits with status 1. A child that exits during the wait exits with that process's status.

For `session/new` and `session/load`, the relay fills a missing, null, or empty `cwd` in params with its workspace, `AgentLink.Paths.workdir()`, before the message reaches the agent. An explicit `cwd` passes through unchanged.

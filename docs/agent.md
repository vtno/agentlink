# Agent

`AgentLink.Relay.Agent` opens one agent through `AgentLink.Agent`. `AgentLink.Agent.Process` is the production behaviour. It runs the `command` and `args` from `AgentLink.Agent.Launch`. The default suite sets `:agent_link, :agent_module` to a fake. `test/lifecycle_test.exs` and `test/release_lifecycle_test.exs` set `AgentLink.Agent.Process` and start `test/fixtures/agentlink_hold_fixture.py`. `test/agent_process_test.exs` starts `test/fixtures/agentlink_setsid_fixture.py`. Stdout still arrives as `{ref, {:data, binary}}`.

`AgentLink.Agent` is that behaviour. `open/3` takes the owner, an `AgentLink.Agent.Launch`, and the workspace. `write/2` and `close/1` stay as they are. A link's `program` is metadata. `opencode` is one example. `program` does not choose the module, the command, or the args. When `program` is missing, `AgentLink.Link` uses `opencode`.

Each `init/1` creates the workspace, then calls `AgentLink.Agent.Launch.load/1` once. That call returns the `AgentLink.Link` and the `AgentLink.Agent.Launch` from the same read. The relay passes that link to `AgentLink.Uplink` as `:link`. The uplink's `init/1` does not read the file again. A watch, a non-parking close, and an uplink started without `:link` call `AgentLink.Link.read/1`. `command` and `args` are not fields of `AgentLink.Link`. Changing only those fields does not redial and does not replace the running process. The next `init/1`, including a supervisor restart, calls `load/1` again. The launch is not stored in the supervisor child arguments.

`AgentLink.Agent.Process.open/3` is the behaviour callback. The relay calls `open/5` for this module and passes `:agent_open_listener`. `open/3` does not read application config. The caller must be `owner`. A bare name is resolved by the finder. `open/4` accepts that finder and is not a callback. The finder `open/3` uses is `&System.find_executable/1`. A path that is absolute on this host is used unchanged. On Unix that path starts with `/`. On Windows it starts with two slashes, or with a drive letter, a colon, and a slash. Each of those two slashes may be `/` or `\`. The slash after the colon may be `/` or `\`. On Windows, a single leading slash is not absolute. Any other command is rejected before `File.stat/1`. `File.stat/1` must report a regular file. `File.stat/1` follows symlinks. `open/3` then calls `Port.open/2` with `{:spawn_executable, path}`, `:binary`, `:exit_status`, `:use_stdio`, `{:args, args}`, and `{:cd, cwd}`. `:env` is the VM environment without `AGENTLINK_WINDOWS_START`. `:stderr_to_stdout` is omitted, so stderr is not merged into `{port, {:data, binary}}`.

## Agent process

On Linux the VM's port spawn makes the command a session leader, and that pid is the process group leader. `close/1` reads `/proc` and records the start time of that pid and of each descendant, including a descendant that called `setsid`. `read_identity/1` reads `/proc/<pid>/stat`. `parse_stat/1` takes the start time from that text. `close/1` signals `SIGTERM` only when that start time still matches. A group leader is signaled with the negative pid. A descendant whose process group is not that pid is signaled by its own pid. `close/1` then closes the port, which closes the child's stdin, and waits up to `:agent_stop_timeout` milliseconds. The default is `5000`. `Application.get_env/3` reads `:agent_link, :agent_stop_timeout`. When a recorded start time still matches, `close/1` reads `/proc` again. `close/1` refreshes each recorded process group through `refresh/1`. `close/1` signals `SIGKILL` to the group leader with the negative pid. `close/1` signals `SIGKILL` to a descendant with that descendant's own pid when the descendant's process group is not that pid. `close/1` waits again. The second wait is `:agent_stop_timeout`, or `1000` milliseconds when that value is shorter, so a timeout of `0` still observes the reap. `close/1` returns `:ok` only when every recorded process is gone. It returns `{:error, :no_kill}` when `kill` is not on `PATH`. It returns `{:error, :kill_failed}` when `kill` exits non-zero and the start time still matches. It returns `{:error, :timeout}` when a start time still matches after `SIGKILL`. Those remaining `{pid, starttime}` pairs are kept by `AgentLink.Agent.Reaper`. When that process is not running, `retain/1` writes the pairs into this VM's file and returns `{:error, :noproc}`, and `close/1` returns that error. A second `close/1` returns `:ok` when no record remains. `close/1` and `AgentLink.Agent.Process.force/1` do not signal pid 1 or this VM's OS pid.

`AgentLink.Relay.Agent.child_spec/1` reads `:agent_stop_timeout` when it builds the child spec. The shutdown is the `SIGTERM` wait, the second wait, and two allowances from `AgentLink.Agent.Process.allowance_ms/0`. `allowance_ms/0` returns `1000` milliseconds for one `kill` and the `/proc` scan before it. The `SIGTERM` wait is `:agent_stop_timeout`. The second wait is that value, or `1000` milliseconds when the value is shorter. The default `:agent_stop_timeout` is `5000`, so both waits are `5000` milliseconds. Two allowances add `2000` milliseconds. The shutdown is `12000` milliseconds. `terminate/2` calls `close/1` and returns when `close/1` returns. At that default, the supervisor kills the relay after `12000` milliseconds when `terminate/2` has not returned.

On macOS, `close/1` closes stdin and does not signal a process group, does not walk descendants, and does not create a Job Object. On Windows, `close/1` closes stdin and does not signal a process group and does not create a Job Object. `write/2` returns `:ok` when the port is open and `:closed` otherwise.

## Reaper

`AgentLink.Agent.Reaper` starts before `AgentLink.Relay.Agent` in the same supervisor. The pairs are written to `agent-reaper-<pid>-<starttime>.bin`, using this VM's OS pid and start time. The file only has to survive a restart of `AgentLink.Agent.Reaper` inside one VM. That file is under `:reaper_dir` when it is set, otherwise under `RELEASE_TMP`, otherwise under `~/.agentlink/run`. The file mode is `0600`. Each write uses its own temporary file. `init/1` reads this VM's file and drops a pid whose start time no longer matches, so a Reaper restart still blocks the next open and does not signal a recycled pid. Another VM's file is removed only when its pid does not exist, or when that pid exists and its readable start time differs from the real start time in the name. A stored start time of `0`, or a start time that cannot be read, is left in place, including on a machine without `/proc`. `init/1` removes this VM's `.bad-*` and `.tmp` files. Another live VM's file is not read and is not signaled. The term is `{:agentlink_reaper, 1, pairs}`. A short file, an undecodable file, a file whose pairs are not a list, or a file whose term has another version is logged and renamed beside the record. Those bytes are not used to signal a process. The next open does not wait on those bytes. Every load, modify, and save of this VM's file, and a clean shutdown's delete, runs inside `:global.trans/3` on `{{:agentlink_reaper, vm}, self()}`, limited to `[node()]`. The requester is the calling process. A `retain/1` during `init/1` waits for that lock and still leaves its pairs for the next `reap/0`. `init/1` verifies the pairs it loaded before it saves them. `retain/1` writes the pairs into this VM's file even when the Reaper is not running, then returns `{:error, :noproc}`. The next relay calls `reap/0` before `open/5` for `AgentLink.Agent.Process`. `reap/0` calls `AgentLink.Agent.Process.force/1`. `close/1` does not call `force/1`. `reap/0` reads the file again. That call signals `SIGKILL` to each retained pid whose start time still matches. `reap/0` waits `1000` milliseconds only after `kill` is found. Without `kill` on `PATH`, `reap/0` returns `{:error, :no_kill}` and does not wait. `reap/0` returns `:ok` when every retained start time is gone. It returns `{:error, :timeout}` when a start time still matches after that wait. It returns `{:error, :kill_failed}` when `kill` exits non-zero and that start time still matches. It returns `{:error, :noproc}` when the Reaper is not running. Any of those errors stops the relay start with `{:stop, {:reap, reason}}` and does not call `open/5`. `init/1` traps exits. A supervisor `:shutdown` runs `terminate/2` within the `2000` millisecond child shutdown, and that delete is inside the same `:global.trans/3`. `Process.exit/2` with `:kill` does not run `terminate/2`, so the file stays.

## Release stop

`bin/agentlink` is the Mix release script. `plane`, `relay`, `connect`, and a leading flag boot the VM and pass those words after `--`. `SIGTERM` stops `plane`, `relay`, and `all`. `start/2` runs in the process `application_master` uses to stop the application, so `Application.stop/1`, `bin/agentlink stop`, and `SIGTERM` shut that tree down. `agentlink connect` installs `AgentLink.ConnectStop` in place of `:erl_signal_handler`. `:erl_signal_handler` calls `:init.stop/0`, and that stop uses status 0. `AgentLink.ConnectStop` logs `SIGTERM received - shutting down`. `AgentLink.ConnectStop` calls `:init.stop(1)`. The status from that call is 1. The connect watcher skips `System.halt/1` when `:init.get_status/0` returns `{:stopping, _}`. `AgentLink.ConnectStop` does not handle `SIGINT`. `SIGINT` opens the Erlang BREAK prompt in every mode, the same as a plain release. The test environment does not install `AgentLink.ConnectStop`.

For `session/new` and `session/load`, the relay fills a missing, null, or empty `cwd` in params with its workspace, `AgentLink.Paths.workdir()`, before the message reaches the agent. An explicit `cwd` passes through unchanged.
